## 概要

機能目的:

- Stripe Checkout から戻ってきた人に、申し込みの結果を正しく伝える

機能概要:

- 有料権限が有効になったかの確認
- 確認中・成功・中断・確認できない、の状態の表示

関連する機能：G-01、G-02

## イベント概要

| No | イベント名 | イベント分類 | 処理説明 |
| --- | --- | --- | --- |
| 1 | 初期表示 | 初期表示 | 申し込みの状態を取得し、状態に合わせた表示にする |
| 2 | 状況を確認する | ボタン押下 | 同じ申し込みの状態を取得し直す |
| 3 | わたしの展示へ | ボタン押下 | [UIS25](../UIS25/README.md) へ遷移（成功のとき） |
| 4 | 契約情報を見る | ボタン押下 | [UIS38](../UIS38/README.md) へ遷移（成功のとき） |
| 5 | プランの案内へ戻る | ボタン押下 | [UIS38](../UIS38/README.md) へ遷移 |
| 6 | 記録に戻る | ボタン押下 | [UIS15](../UIS15/README.md) へ遷移 |

### 1. 初期表示

起動パラメータ:

| Name | Value | Memo |
| --- | --- | --- |
| result | `success` または `canceled` | Stripe Checkout の戻り先の URL に付ける。表示の手がかりにだけ使い、契約の判定には使わない |

利用API:

| ID | 処理 | Parameter |
| --- | --- | --- |
| API75 | 本人の申し込みの状態と有料権限を取得する | なし |

画面表示制御：サーバーが持つ状態で、次のように表示を変える

| 状態 | 表示 | 画面モデル |
| --- | --- | --- |
| 有料権限をまだ確かめられない（API75 の `state` が `checkout_pending`、または `result=success` で戻ったのに `state` が `none`） | 「ご利用状況を確認中です」・「状況を確認する」・記録に戻る導線 | `billing_checkout_pending` |
| 有料権限が有効になった | 「展示プラスをご利用いただけます」・わたしの展示と契約情報への導線 | `billing_checkout_success` |
| 申し込みを中断して戻った | 「お申し込みを中断しました」・プランの案内と記録に戻る導線 | `billing_checkout_canceled` |
| 支払いの状況を確かめられない | 「お支払いの状況を確認できませんでした」・「状況を確認する」・プランの案内へ戻る導線 | `billing_checkout_error` |

- 有料権限は、Stripe からの通知（Webhook）を決済用キューで処理した結果で有効になる（G-02）。Stripe から戻ったことだけでは、成功とみなさない
- 成功の表示は、有料権限が有効だと確かめられた場合だけ出す
- 中断して戻った場合でも、有効化の通知と行き違っていることがあるため、サーバーが持つ状態を優先する
- 確認中の表示に、残りの時間や進み具合の割合は出さない
- 確かめられない状態を、「請求なし」「未払い」と言い切って表示しない

### 2. 状況を確認する

イベント 1 と同じ API で、同じ申し込みの状態を取得し直す。新しい申し込みや決済は作らない。

画面表示制御:

- 支払い情報の確認が必要と分かった場合は、[UIS38](../UIS38/README.md)（支払い情報の確認が必要な状態）へ遷移する
- 申し込みが成立しておらず、有効な契約もないと確かめられた場合は、[UIS39](../UIS39/README.md) へ遷移する
